TimeSense — Google & Apple sign-in setup
========================================

App code is ready. You must enable providers in Google / Apple / Supabase.

Your Supabase project URL:
  https://pwgspnqodaokmkoyghcu.supabase.co

Callback Supabase always uses (add this to Google & Apple):
  https://pwgspnqodaokmkoyghcu.supabase.co/auth/v1/callback

---------------------------------------------------------------------------
A. Supabase redirect URLs (do this first)
---------------------------------------------------------------------------
1. Dashboard → Authentication → URL Configuration
2. Site URL: timesense://auth/callback
3. Additional Redirect URLs — add ALL of:
   - timesense://auth/callback
   - timesense://**
   - exp://**                    (Expo Go on device)
   - http://localhost:8081/**    (web testing)

---------------------------------------------------------------------------
B. Google (required for "Continue with Google")
---------------------------------------------------------------------------
1. Open https://console.cloud.google.com/ → create/select a project
2. APIs & Services → OAuth consent screen → configure (External is fine for testing)
3. APIs & Services → Credentials → Create credentials → OAuth client ID
   → Application type: Web application
   → Authorized redirect URIs:
       https://pwgspnqodaokmkoyghcu.supabase.co/auth/v1/callback
4. Copy Client ID and Client Secret
5. Supabase → Authentication → Providers → Google → Enable
   → paste Client ID + Client Secret → Save

---------------------------------------------------------------------------
C. Apple — native iOS (Expo Go / iPhone)
---------------------------------------------------------------------------
Apple Sign-In on iOS uses identity tokens (no browser).

1. Supabase → Authentication → Providers → Apple → Enable
2. Client IDs (comma-separated), include at least:
   - host.exp.Exponent          ← required for Expo Go testing
   - com.timesense.app          ← your app bundle id (dev builds / store)
3. For Expo Go testing you can leave Secret Key empty if you ONLY use
   native Sign in with Apple on iOS (signInWithIdToken).
4. On a real iPhone with Expo Go: Auth screen → Continue with Apple

Notes:
- Apple button only appears on iOS devices that support it (not Android emulator).
- App Store rule: if you offer Google (or any other social login), you MUST
  also offer Apple Sign-In on iOS — we already do.

---------------------------------------------------------------------------
D. Apple — Android / web browser OAuth (optional, more setup)
---------------------------------------------------------------------------
Only needed if you want "Continue with Apple" outside native iOS.

Requires an Apple Developer paid account:
1. Certificates, Identifiers & Profiles → Identifiers → Services ID
2. Enable Sign in with Apple → configure Return URL:
   https://pwgspnqodaokmkoyghcu.supabase.co/auth/v1/callback
3. Create a Sign in with Apple key (.p8), note Key ID + Team ID
4. Supabase Apple provider:
   - Services ID first in Client IDs list (for web OAuth)
   - then host.exp.Exponent and com.timesense.app
   - Secret Key generated from .p8 / Team ID / Key ID (Supabase docs have a generator)

---------------------------------------------------------------------------
E. Test
---------------------------------------------------------------------------
1. Restart Expo (npm start) after any .env / app.json change
2. Open Auth → Continue with Google (works on **web and Android Expo Go**)
3. On iPhone: Continue with Apple
4. Home should show "Signed in as …"

Android-specific steps: see supabase/ANDROID_GOOGLE_AUTH.txt

Dev tip: the Auth screen shows the live OAuth redirect URI under the buttons
in __DEV__ — copy that exact string into Supabase Redirect URLs if sign-in
returns to the browser but not the app.
