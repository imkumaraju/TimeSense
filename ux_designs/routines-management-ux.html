When does the reminder actually fire?

Same-day save, time still ahead — fires today

Save routine — 2:00 PM
Reminder fires — today, 9:00 PM

A WEEKLY expo-notifications trigger computes its next firing forward from the moment it's scheduled. If today is a selected day and the reminder time hasn't passed yet, that's the first firing — no waiting a week.

Same-day save, time already passed — skips to next week

9:00 AM (missed)
Save routine — 2:00 PM
Reminder fires — next Friday, 9:00 AM

It never fires "late" the same day to make up a missed time — the trigger only looks forward. If the reminder time for today has already gone by when you hit Save, the routine still shows correctly under Today's Routines (that's a separate, on-device isDueOnDate check, not tied to the notification), but the OS reminder itself waits for the next matching weekday.

  • Practical effect: setting up "Leg Day, Friday 9 AM" at 2 PM on a Friday means you won't get pinged today — only starting next Friday. The card is still visible and tappable on Home today, it just won't nudge you.
Implementation notes — for whoever builds this next:
  • lib/routinesDb.ts already has listRoutines() (all routines, any day/active state) — the list screen is a straight read, no new query needed.
  • No updateRoutine() exists yet — edits currently only happen through setRoutineActive() (pause/resume). Editing name/days/time/duration needs a new function in routinesDb.ts that patches the row, bumps updated_at, sets synced = false, and calls rescheduleRoutineNotifications() again afterward (cancels the old weekly triggers, schedules new ones from scratch — there's no partial-update path for OS-scheduled notifications).
  • Suggested routes: app/routines/index.tsx (list, screen C) and app/routines/[id].tsx or reuse app/timer/new.tsx's Repeat panel in an "edit mode" (screen D) — the day-chip / time-picker / segmented-control components built for New Timer's Repeat toggle are directly reusable here.
  • Entry points: a "See all ›" link next to the "Today's Routines" label in app/(tabs)/index.tsx, and a "Routines" row in the Timer section of app/(tabs)/settings.tsx — both push to the same list screen.
  • Delete already exists (deleteRoutineFully in lib/routineNotifications.ts) — reuse as-is for screen D's Delete button and the quick-action sheet.
